# Tarea 1

En esta tarea aplicarás el framework de formulación de proyectos que revisamos en clase (Materiales 01 y 02) a un problema real.

Para ello, trabajarás **en pareja** y explorarás proyectos publicados por organizaciones que buscan utilizar ciencia de datos para resolver problemas de impacto social.

> Se evaluará principalmente su capacidad para **discutir y razonar sobre el problema**, identificar metas y acciones concretas, y conectar los datos y el análisis con una decisión real.

**No es necesario escribir respuestas extensas.** Respondan de manera concreta, preferentemente mediante viñetas. Lo importante es la claridad de su razonamiento.

## Paso 2. Formulen el proyecto usando el framework de *scoping*

Discutan cada apartado entre ustedes y registren **únicamente las conclusiones principales**. Como referencia, intenten utilizar **entre 2 y 4 viñetas por sección**.

### 0. Problema

Identifiquen:

* ¿Cuál es el problema real que se quiere atender?
* ¿A quiénes afecta y, si existe información, cuál es su magnitud?
* ¿Por qué es relevante para la organización?

### 1. Meta

Definan:

* ¿Qué resultado **concreto, específico y medible** se busca alcanzar?
* ¿Qué tendría que cambiar para poder decir que el proyecto tuvo éxito?

> La meta **no** es construir un modelo, hacer un mapa o desarrollar un dashboard. Esos productos son medios para alcanzar una meta.

### 2. Acción

Identifiquen:

* ¿Qué acción, programa, intervención o decisión puede tomar la organización?
* ¿Quién realiza esa acción?
* ¿Sobre quién o qué se actúa?
* ¿Cuándo o con qué frecuencia podría realizarse?

### 3. Datos

Describan:

* ¿Qué información necesitarían idealmente para apoyar esa acción?
* ¿Cuál sería la unidad de observación? Por ejemplo: personas, escuelas, lugares, transacciones, solicitudes, imágenes, textos, etc.
* ¿Qué limitaciones podrían tener esos datos?

> No necesitan identificar una base de datos específica. Piensen en **qué información sería necesaria idealmente** para resolver el problema.

### 4. Análisis

Expliquen:

* ¿Qué tipo de análisis sería útil?
* ¿Qué resultado produciría ese análisis?
* ¿Cómo utilizaría la organización ese resultado para tomar la **acción** que identificaron anteriormente?

### 5. Ética

Identifiquen **uno o dos riesgos éticos concretos** del proyecto.

Pueden considerar:

* privacidad;
* posibles sesgos;
* inequidades;
* errores del modelo;
* grupos que podrían verse perjudicados;
* consecuencias no deseadas de utilizar el análisis para tomar decisiones.

No es necesario discutir todos estos temas; elijan los que sean relevantes para su proyecto.


## Paso 3. Reflexión final

Respondan **brevemente, entre ambos**, en un máximo de **1/3 de página en total**:

* ¿Qué parte del framework fue más difícil de definir y por qué?
* ¿El proyecto les parece suficientemente accionable tal como está planteado?
* ¿Qué cambiarían o qué información adicional necesitarían para formularlo mejor?


## Tomen en cuenta

* No elijan necesariamente el proyecto más técnico. Elijan uno que les permita razonar sobre el **problema, las personas afectadas y las decisiones que podrían tomarse**.
* Si la descripción de la plataforma es vaga, pueden hacer **suposiciones razonables**, pero deben señalarlas.
* Algunos proyectos pueden estar formulados de manera poco clara. **No tienen que aceptar la formulación original:** pueden replantearla utilizando el framework visto en clase.
* Recuerden la distinción del Material 01: muchas aplicaciones de ciencia de datos no buscan responder *por qué falla el sistema*, sino ayudar a decidir **dónde, cuándo o sobre quién actuar primero**.
* No se evaluará la cantidad de texto. Se evaluará la **claridad y coherencia entre problema → meta → acción → datos → análisis**.

## Rúbrica


| Sección         | Excelente (100%)                                                                                                     | Suficiente (70%)                                                      | Insuficiente (40%)                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **0. Problema** | El problema, la población afectada y su relevancia están claramente identificados.                                   | El problema se identifica, pero falta precisión o contexto.           | No queda claro cuál es el problema real.                                |
| **1. Meta**     | La meta es concreta, específica y medible; se entiende qué cambiaría si el proyecto tiene éxito.                     | Existe una meta, pero es vaga o difícil de medir.                     | La meta se confunde con un producto o análisis técnico.                 |
| **2. Acción**   | Se identifica claramente qué acción se tomaría, quién la realiza y sobre quién o qué.                                | Existe una acción, pero está poco operacionalizada.                   | No existe una acción clara o el análisis se plantea como el objetivo.   |
| **3. Datos**    | Se identifica con claridad qué información sería necesaria, su unidad de observación y sus principales limitaciones. | Los datos se describen de manera general.                             | Los datos no se especifican o no corresponden con el problema.          |
| **4. Análisis** | El análisis está justificado y existe una conexión clara entre su resultado y la acción.                             | Se propone un análisis, pero su relación con la acción es poco clara. | El análisis no corresponde con el problema o no informa ninguna acción. |
| **5. Ética**    | Se identifican riesgos éticos específicos y relevantes para el proyecto.                                             | Se mencionan riesgos éticos de manera general.                        | No se identifican consideraciones éticas relevantes.                    |
